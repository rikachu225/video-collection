# Changelog

## v2.8.3 - 2026-09-27
### Security
- **No more CORS: browser requests must come from the app's own origin `[MED]`.** `CORS(app)` let any website the user visited read and write this API, and the IP-based LAN guard can't tell a hostile page from the app — both arrive from the user's own browser, so from `127.0.0.1` or the LAN. `flask-cors` is removed from `requirements.txt`, and a new `_same_origin_only` guard runs after the LAN guard. The `Host` header must be `localhost`, a loopback/private/link-local IP literal, or this machine's own name (hostname, `<hostname>.local`, FQDN, and for a fully qualified hostname such as `media-box.example.lan` also `media-box` and `media-box.local`, the name mDNS advertises) — that blocks DNS rebinding. `POST`/`PUT`/`PATCH`/`DELETE` are refused when `Origin` differs from the app's own `scheme://host` or `Sec-Fetch-Site` is `cross-site` — that blocks cross-site writes. Requests that send neither header (curl, scripts) are left to the IP guard. Opening the app by LAN IP, `localhost`, `127.0.0.1`, `[::1]` or the desktop window is unaffected; any other local name (a router DNS alias, a hosts-file entry, a monitor's `host.docker.internal`) now gets a 403 until it is listed in `VIDCOL_ALLOWED_HOSTS=media.lan,nas.home`. README's Security Notice now documents this.
- **Other sites can no longer probe the API through `<img>`/`<video>` `[MED]`.** Such a GET can't read the body, but onload vs onerror leaked which custom services and library paths exist, and a GET of `/api/service-icon/<id>` started an outbound lookup. Every `/api` and `/api/*` request, any method, is now refused when `Sec-Fetch-Site` is `cross-site` or `same-site` (another port on this machine counts as same-site). No header (curl, monitors), `same-origin` (the app itself) and `none` (a typed URL or bookmark) pass, and pages outside `/api/` are not checked, so other sites can still link to the app. Browsers send this header only to https and loopback origins, so on a plain-http LAN IP such a request still reaches the server (only an enabled service is ever looked up). That case is closed on the browser side instead: every `/api` response, whatever its status (200, 304, 4xx, the guards' 403s, a 500), now carries `Cross-Origin-Resource-Policy: same-origin`, so the browser fails another site's `<img>`/`<video>` load of it like a network error and onload vs onerror reveals nothing. By design, no other origin can embed the app's videos or thumbnails any more (a Home Assistant card, for example); links, bookmarks, the desktop window and the app itself are unaffected.
- **Other sites can no longer frame the app `[LOW]`.** Any page could load the app in an `<iframe>` and trick clicks onto its one-click actions (hide a folder, Refresh Icons, load a playlist), getting around the cross-site write refusal because the framed app's own requests are same-origin. Every HTML response now carries `X-Frame-Options: SAMEORIGIN` and `Content-Security-Policy: frame-ancestors 'self'`; a CSP a route sets itself keeps its directives and only gains `frame-ancestors`. The desktop window loads the app top-level and is unaffected.
- **Hidden services were still looked up `[LOW]`.** README Privacy promised that hidden services are never looked up, but any GET of `/api/service-icon/<id>` for a hidden built-in fetched its icon (8+ outbound requests). A lookup now starts only for a configured and enabled service; a hidden or unknown id is a 404 with no outbound request and no miss marker. A drop-in, or an icon cached before the service was hidden, is still served. The app itself never requested hidden icons, so nothing visible changes.
- **The icon fetcher's SSRF guard let CGNAT and tunnelled IPv4 through `[MED]`.** `_is_public_ip` only checked the refusal flags, and none of them is set for `100.64.0.0/10` (the range Tailscale uses). It now also requires `is_global` (plus `is_site_local` for deprecated `fec0::/10`), and an IPv6 address that embeds an IPv4 one — IPv4-mapped, 6to4, Teredo (server and client) — counts as public only if the embedded IPv4 does. NAT64 (`64:ff9b::/96`, `64:ff9b:1::/48`) is refused outright, even when it embeds a public IPv4, by an explicit check that doesn't depend on `is_reserved`; on a DNS64/NAT64-only network, icons from IPv4-only hosts therefore can't be fetched. The docstring that credited `is_private` with covering CGNAT is corrected.
- **The icon fetcher dials only the addresses its SSRF check approved `[LOW]`.** The check and the connect resolved the host separately, so a DNS answer that changed in between (rebinding, the residual noted in v2.8.1) reached the dial unchecked, and so did a percent-encoded host: `urlparse` keeps `%2e` in the name the check resolved, while urllib connects to the unquoted name. One `_IconLookup` per lookup now resolves each host once, and the check and the connect both read that answer; `_icon_connect` refuses the host unless every address in it is public and dials exactly those addresses. A hostname containing `%` is refused before it resolves. Only the hop to an https proxy is exempt, because the proxy resolves the target itself.
- **A hostile homepage could freeze the server for minutes `[MED]`.** The regexes that pulled `<link rel="icon">` tags out of a fetched page backtracked quadratically on unterminated markup, and parsing holds the GIL, so one crafted page stalled every waitress thread. Handing the whole page to `html.parser.HTMLParser` is no cure: on CPython 3.11.9 it rescans to the end of the input from every later `<`. `_icon_links()` now cuts each `<link` at the next `>` within 2048 chars and parses only that bounded fragment, at most 64 icon tags per page, so the work is linear in the page size. Ranking is unchanged.
- **Each icon lookup has an overall time and request budget `[LOW]`.** `ICON_TIMEOUT` (12s) applied per socket call, and http.client reads the status line, headers and chunk framing through many small reads, so a server sending one byte at a time could hold a worker thread (and every request queued on that service's lock) for as long as it kept going. One 20s `ICON_BUDGET` deadline now covers the homepage, every candidate and every redirect, and it is enforced on every blocking socket call: `_DeadlineHTTPSConnection` re-arms the timeout to the time left before each connect (all resolved addresses share the deadline), TLS handshake, send and receive — request, status line, headers, chunk-size lines, trailers and body — and fails once the deadline has passed. DNS is inside the budget too: `getaddrinfo` takes no timeout, so it runs in a worker thread that the lookup stops waiting for when the budget is spent. Each host is resolved once per lookup and a failure is remembered, so a service whose host doesn't resolve fails once instead of once per candidate (measured with DNS taking 2s to fail: 4 resolutions and 8s per icon before, 1 and 2s now). When a host has several addresses, each one but the last may take at most 4s (`ICON_CONNECT_SLICE`) to connect, and the one that accepts is dialled first for the rest of the lookup, so a dead first address (a blackholed IPv6 route, one dead CDN edge) can't eat the budget: v2.8.2 found such a host's icon slowly, and a 20s budget with a 12s wait per dead dial would have made it a miss. A lookup that timed out anywhere, got a DNS "try again" (`EAI_AGAIN`) or ran out of budget is negative-cached for 1h (`ICON_TIMEOUT_MISS_TTL`, marker body `timeout`) instead of 24h, since the site may be fine. Certificate and hostname checks are unchanged, and https proxies still work. Bodies are still read with `read1()` in 64KB chunks. A body shorter than its `Content-Length`, and `IncompleteRead`/`HTTPException`, now count as failures instead of a truncated body being cached or an exception surfacing as a 500 — including an `HTTPException` raised while the connection is opened (a bad or HTTP/2 status line, more than 100 headers, an overlong header line, or `InvalidURL` for a space in an icon href), which returned a 500 and recorded no miss. So does a redirect whose `Location` can't be parsed: Python 3.10 has no 308 handler, so a 308 with `Location: https://[bad/` escaped as a 500 on every render.
- **At most 8 icon URLs per lookup `[LOW]`**, so a page declaring hundreds of icons can't turn one lookup into hundreds of third-party requests. `/apple-touch-icon.png`, `/apple-touch-icon-precomposed.png` and `/favicon.ico` always keep their slots; the cap drops only page links (at most 5 kept), and non-https hrefs don't take a slot.
- **Assistant: streaming service names reach the system prompt as a JSON array**, labelled as data, instead of comma-joined free text that a crafted service name could use to append instructions.

### Fixed
- **Settings → Streaming only saved the first edit.** Every save replaces `state.streamingServices` with fresh objects from the server response, but each row kept editing the object it was rendered from — so the second toggle, URL edit or delete changed an object nothing posted (delete even toasted success), and ↑/↓ used a captured index. Rows now look their service up by id when the event fires (`currentStreamingService`), delete filters by id, and `moveStreaming(id, delta)` moves by id, so repeated clicks work.
- **"Open Netflix" failed on a fresh page load.** Only the Streaming view and Settings filled the service list, so the assistant's `open_streaming_service` matched nothing. `openStreamingService()` is now async and fetches `/api/streaming` when the list is empty — data only, no render, so no icon requests. The assistant awaits its UI commands one at a time, in the order the model issued them, still after `applyRefresh()`.
- **The assistant claimed it had opened a service when the browser blocked the popup.** The command runs after an LLM round trip, by which time the click's user activation has usually expired, and with `noopener` `window.open` returns `null` even when it works, so its result can't reveal a block. The app now asks `navigator.userActivation.isActive`: while the gesture is live it opens the tab as before; otherwise it shows a toast with a real **Open <service>** link (`target=_blank`, `rel="noopener noreferrer"`, no referrer) that stays 10s. An empty service name no longer launches whichever service is first in the list.
- **Streaming icons went stale behind a 7-day browser cache.** Icons are now served with `Cache-Control: no-cache` and a strong ETag that is a digest of which file is served (drop-in or fetched) and its bytes, so an unchanged icon costs one 304 and a refetched or newly dropped-in one is picked up when the tile's image is requested again — even a same-size refetch written within one tick of a coarse file clock (Linux), which a size + mtime tag missed. The digest is cached per file and reused only while its size, mtime, ctime, inode and device all match and it had been unchanged for 2s before it was hashed; no `Last-Modified` is sent. Tile icon URLs now carry `?v=2`, so icons that v2.8.2 cached for 7 days under the bare URL are never reused after the upgrade; **Refresh Icons** also adds `&t=<ms>`, because within one page an unchanged image URL can be reused without asking the server. Because the cache is keyed by id, saving the streaming list now clears the fetched icon and miss marker of any service whose site (origin) changed or that was removed; a path-only change keeps the icon, and a drop-in is never touched.
- **A save or Refresh Icons wins over an icon lookup already running.** A lookup that was in flight when the list was saved or Refresh Icons was clicked wrote its result after the clear: a re-pointed service kept the old site's icon, or a 24h miss marker hid its icon for a day. Each id now has a generation that every clear bumps without waiting for the lookup; a lookup reads it before the service's URL and writes its icon or miss marker only if it is unchanged, otherwise it discards the result. A request queued behind a lookup now uses the URL saved meanwhile.
- **Icon cache writes are atomic, and parallel first requests share one fetch.** A fetched icon is written to a dot-prefixed temp file and `os.replace()`d into place, so a failed write leaves nothing behind instead of a truncated file that was then served; miss markers are written the same way. A failed write (a full disk, a temp file locked by AV or a sync client) was silent and re-ran the whole outbound lookup on every render: it is now logged with the file name and holds that service off for 5 minutes, in memory only — no miss marker, so a passing disk problem can't hide the icon for a day, and Refresh Icons retries at once. A per-service lock re-checks the cache before fetching, so tiles requested at the same moment on waitress's threads no longer each fetch the same icon.
- **A locked icon file turned a saved streaming list into a 500.** On Windows a cached icon held open (a response in flight, an AV scan, a sync client) can't be deleted, and the `PermissionError` escaped after the new list was already saved. Removing a cached icon or miss marker now logs a warning and leaves the file until the next clear; the save, Refresh Icons and a successful fetch all complete. A file left behind this way is marked stale in memory: it is never served and never counts as a miss, so a re-pointed service never shows the old site's icon (it looks the new site up instead). When that lookup commits its result (an icon of any type, or a miss) it retries the delete of every stale file for the service, which succeeds once the lock has gone, so an old `.png` can't outlive the mark and outrank the new site's `.svg` after a restart.
- **One validator for streaming reads and saves (`_normalize_service`).** A hand-edited `config.json` with a non-string name crashed `GET /api/streaming`; `enabled: "false"` was coerced to `true`; a non-object `POST` body returned a 500; a save could store an id (a de-dup suffix past 48 chars) that the next read dropped; and an id-less custom entry could take a built-in's id. Wrongly typed fields are now dropped on read and a 400 on save, explicit ids are claimed first, derived ids never take a shipped default id, and de-dup suffixes fit inside the 48-char limit.
- **Late clip metadata re-tiled a workspace the user had arranged.** v2.7.1 cancelled the pending re-layout when a panel was dragged, but every clip whose metadata arrived afterwards armed a new one and snapped the panels back. A real drag or resize now sets `wsUserArranged`, which blocks late re-tiling until the next auto-tile (the Tile button, the assistant's `bento_workspace`, or a workspace opened without a saved layout). A click that only raises a panel doesn't count.
- **A narrower grid never re-clamped bento column spans.** Only row spans were recomputed on a window resize, and nothing at all when the sidebar was toggled (that fires no window resize, and the sidebar starts collapsed at tablet width), so a narrower grid kept spans wider than itself (CSS Grid then invents implicit columns and squeezes cards into them) and a wider one never gave back the stored size. A `ResizeObserver` on the two grids now re-clamps column spans in both directions whenever a grid's width changes, whatever changed it (`reclampBentoGrid`, 150ms debounce), then row spans; a window resize listener remains only where `ResizeObserver` doesn't exist. `#main` always reserves its scrollbar gutter, so a re-clamp that changes a grid's height can't change its width and set off another. The clamp measures the grid's own columns with every tile at span 1: the resolved `gridTemplateColumns` also lists the implicit columns an oversized span creates, so clamping against it kept a 3-wide card 3 wide in a 2-column grid. Browse is also re-clamped when you return to it from another view with a folder open, because a grid hidden during the resize resolves no tracks; the theater re-renders on return. Browse cards carry `data-path` for the lookup; the tile being dragged keeps its span.
- **Toasts covered the assistant orb and took its clicks.** The toast stack and the orb share the bottom-right corner, and a toast with a link takes clicks, so clicking the orb to open or close the chat opened the streaming service instead. `placeToasts()` now moves the stack clear of the orb and the open chat panel wherever the orb has been dragged — sliding left, or above/below them in a narrow window — and follows the orb and panel as they move, show or hide. An action toast takes clicks only while shown, so a fading one lets them through.
- **Resizing a dragged (pinned) assistant panel made it jump back on reopen.** The top-left grip moves the panel's corner, but only `aiPanelSize` was saved. `aiPanelPos` now follows the resize when the panel is pinned; an orb-anchored panel stays anchored.

### CI & Docs
- **CI actually runs the suite.** The `lint-and-test` matrix (ubuntu/windows/macos × Python 3.10/3.11/3.12) installs `requirements.txt` + `requirements-dev.txt` and runs `python -m pytest -q` with `VIDCOL_DATA_DIR` pointed at a fresh dir under `runner.temp`; before, it only `py_compile`d two files. "Verify server starts" really imports `server.py` and asserts `GET /api/health` is 200 through the test client — the old step built a module spec and never executed it. Steps run under bash on every OS, with 2- and 10-minute timeouts. The Flask version is read via `importlib.metadata`, since `flask.__version__` is removed in Flask 3.2.
- **The secret scan can fail.** The old step could never fail and matched variable names like `GEMINI_API_KEY`. It now scans every tracked file for secret *value* shapes — Google `AIza…`, `sk-`/`sk-proj-`/`sk-ant-` keys, GitHub `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` and `github_pat_` tokens, AWS `AKIA`/`ASIA` ids, Slack `xox[baprs]-` tokens, PEM private-key blocks — prints only `file:line` and the rule name, and fails the job on any hit. Each file is scanned byte-for-byte (ASCII, UTF-8, the text inside binaries). A byte scan can't see a key stored as UTF-16 (a Windows PowerShell 5.1 `>` redirect, a `.reg` export), so a file that starts with a UTF-16 or UTF-32 BOM is also decoded and scanned; one that doesn't decode is named in the log and treated as binary. Any other file containing NUL bytes is also scanned with the NULs removed, which covers BOM-less UTF-16/32. Compressed or encoded content (a zip, a base64 blob) is not covered.
- **README Privacy is accurate again.** It said nothing leaves your machine; since v2.8.1 the server fetches streaming icons. It now lists everything that goes online — icon fetches (what is requested, when, and how to opt out by hiding a service or dropping in your own icon), `yt-dlp` URL downloads, and the BYOK assistant, including exactly what the assistant sends to Google Gemini: the chat, a snapshot of the app's state (clip names and paths relative to their media source, playlist and theater names), the enabled streaming tile names, and what its actions return — which includes the full disk paths of your media sources when you ask it to create a folder, and search results from hidden folders — and adds a Streaming Launcher feature section and `data/service_icons/` to the project structure. It says exactly what the icon fetcher's user agent is: it names the app and its version (`VideoCollection/2.8`), not a generic browser.
- **README Security Notice documents the Host allowlist**: which names work (including a fully qualified hostname's short and `.local` names), `VIDCOL_ALLOWED_HOSTS` with an example, and that uptime monitors must use `localhost`, an IP or an allowed name. It also says other sites can neither read the app's `/api/` responses nor frame it, and that this rules out embedding the app's videos or pages elsewhere.

## v2.8.1 - 2026-07-31
### Added
- **Official app icons on the streaming tiles.** The server resolves each service's icon (standard `apple-touch-icon` paths → the homepage's declared `<link rel="icon">` tags, ranked by their `sizes` attribute → `favicon.ico`), downloads it once, and caches it in `data/service_icons/auto/`. Measured result across the 11 built-ins: **10 resolve**, 8 of them at 144–256px. The size-ranked HTML parse matters — Netflix serves *nothing* at the standard paths (only a `<link>` tag), and it lifted Disney+, Peacock and YouTube well above what their bare favicons would have given.
- **Bring your own icon.** Drop a PNG named after the service id into `data/service_icons/` (e.g. `crunchyroll.png`) and it always beats the fetched copy — that's the fix for Crunchyroll (serves no discoverable icon) and Prime Video (48px, soft on a 4K display). A **Refresh Icons** button in Settings clears the fetched cache and busts the browser's 7-day image cache so a file you just dropped in shows up immediately.
- Icons live entirely in `data/` (now gitignored), fetched by *your* install for *your* use — so the public repo still ships **zero third-party brand assets**, and the app stays offline-capable after the first fetch. Nothing is hotlinked at render time.

### Security
- **SSRF guard on the icon fetcher `[HIGH]`.** The server now fetches URLs derived from user-editable service entries, so a custom service pointed at `https://192.168.1.1/` would otherwise have the server request your router from inside the LAN. Every hostname is resolved and **every** address it returns must be public — `is_private`, `is_loopback`, `is_link_local` (this is what blocks the `169.254.169.254` cloud-metadata endpoint), `is_multicast`, `is_reserved` and `is_unspecified` are all refused, IPv4 and IPv6. Redirects are handled manually precisely so each hop is re-checked rather than trusted.
- Fetches are https-only, capped at 2MB and 4 redirects with a 12s timeout, and the response content-type must be on an image allow-list — an HTML or JSON body is discarded, never cached. Cache filenames come from the already regex-validated service id, so there is no path-traversal surface.
- Failed lookups are negatively cached for 24h, so a service with no icon can't cause a fetch storm on every page load.
- Residual `[LOW]`: DNS rebinding between the resolve check and the connect. Closing it fully means pinning the resolved IP and connecting with an explicit `Host` header — not worth the machinery for a LAN-guarded local app, but noted. *(Closed in v2.8.3: the connect now dials only the addresses the check approved.)*

### Fixed
- Tiles render text-only when no icon exists (the `<img>` removes itself on error), so a missing logo can never leave a broken-image box. Verified: Crunchyroll degraded cleanly before a drop-in was supplied.

## v2.8.0 - 2026-07-31
### Added
- **Streaming view — launcher tiles for Netflix, Max, Disney+, Prime Video, Hulu, Apple TV+, Peacock, Paramount+, YouTube, Crunchyroll and Twitch.** A fourth top-level view (sidebar + mobile tab bar) that opens a service in a new tab. Tiles are brand-accent glass with the service name in the app's type scale — deliberately **no logo assets**, so the app stays offline-capable (nothing hotlinked), ships no third-party marks in a public repo, and matches the existing aesthetic. Everything is configurable in **Settings › Streaming**: hide any service, reorder with ↑/↓, re-point a URL (send Netflix to a profile, Max to a hub), or add your own. Custom services get a stable accent derived from their name so they don't all render identical cyan.
- **`open_streaming_service` assistant tool.** "Open Netflix", "put on Crunchyroll" launch the service. Matching is exact name → id → partial name → hostname, so "disney" finds Disney+. The system prompt carries the *enabled* service names, so the assistant recommends only what you actually have configured, and is told plainly that these services can't be played inside the app so it never offers to. `switch_view` gained `streaming`.

### Security
- **URL validation is server-side, at a single write path.** `POST /api/streaming` replaces the whole list, so add / edit / reorder / hide all pass through one validator: **https only**, no embedded credentials, no control characters, 2048-char cap, max 100 services. A `javascript:` or `data:` URL here would be script execution in the app's own origin, so the browser-side check is deliberately *not* the only gate. The whole payload is rejected on any bad entry rather than partially saved. `_streaming_services()` (the read path) instead drops invalid entries silently, so a hand-edited `config.json` can never take the app down.
- **Accent colours are validated to six-digit hex.** They land in an inline CSS custom property, where an arbitrary string is a CSS-injection vector.
- **Every tile is an `<a rel="noopener noreferrer" referrerpolicy="no-referrer">`.** Without `noopener` the opened page receives `window.opener` and can navigate this app elsewhere (reverse tabnabbing). A real anchor also keeps middle-click, Ctrl-click and keyboard activation working.

### Notes
- **Netflix, Max and Disney+ cannot be embedded, and this is not a limitation that can be engineered around.** Measured: Netflix returns `X-Frame-Options: DENY`, Max returns `frame-ancestors 'none'` — both enforced by the browser, not the page. Independently, their playback runs through EME/Widevine, which binds licences to a verified player on an authorised origin, so even a frame that *loaded* would get no key. Deliberately circumventing that is DMCA §1201 territory. Hence launcher tiles, not embeds. YouTube, Vimeo and Twitch **do** publish embed endpoints (verified: no framing headers) if in-app embedding is ever wanted — that would be a separate feature with a `frame-src` CSP allowlist.

## v2.6.3 - 2026-07-30
### Fixed
- **Bento layout dumped most clips into one tiny row.** The row split was count-based: it closed a row once its aspect sum passed `total / R`, but the guard `rows.length < R - 1` meant the final row could never close — so it absorbed *every* remaining clip. The result was a few normal-sized panels on top and a strip of ultra-small ones underneath. Rows are now built by **target height** (the standard justified-gallery approach): clips are added to a row until justifying it to the canvas width would drop it below the target, then the row closes, so no row can absorb the remainder. The target height itself is binary-searched for the tallest value whose stack still fits the canvas. With 12 mixed portrait/landscape/square clips the split is now 6 + 6 with a tallest-to-shortest row ratio of 1.16 (was one normal row plus a tiny strip), and every panel's aspect is still exact. An under-full final row is capped at the target height so it can't balloon.
